# 文件与资源管理

整理文件时，先区分游戏必需资源、开发资料和临时产物。当前项目保留早期素材及生成器依赖；源码按职责分目录维护；素材生成器及历史资源保留。

## 放在哪里

| 位置 | 内容 | 是否提交 |
| --- | --- | --- |
| 项目根目录 | Godot 工程配置与说明 | 是 |
| `scenes/` | Godot 场景 | 是 |
| `scripts/core/`、`scripts/gameplay/`、`scripts/render/`、`scripts/ui/` | 核心、玩法、绘制、界面脚本 | 是 |
| `scripts/data/`、`locales/` | 地图、剧情与离线翻译目录 | 是 |
| `assets/` | 游戏实际使用的图片、音乐、音效、字体、shader 和素材制作记录 | 是 |
| `tools/` | 素材制作、构建及 harness 工具 | 是 |
| `docs/`、`docs/screenshots/` | 持续维护的说明与文档引用的精选配图 | 是 |
| `licenses/` | 字体等第三方授权声明 | 是 |
| `.godot/`、`*.import` | Godot 缓存和导入记录 | 否 |
| `dist/`、`build/`、`*.app/`、`*.pck` | 引擎运行时、导出应用和安装包 | 否 |
| `/tmp/paopaotang-*` | 检查报告、日志、检查存档、临时截图和预览 | 否 |

游戏资源中的 PNG、OGG、WAV 和字体需要随源码保留，下载工程才能直接运行。禁止提交的二进制产物是引擎、编译结果和发布包；不能把所有非文本文件都忽略。

## `.uid` 是什么

`.uid` 是 Godot 为脚本、shader 等资源保存的唯一标识文件。例如 `game.gd.uid` 保存 `game.gd` 的资源身份，内容通常是一行 `uid://…`。它是很小的文本文件，不是编译结果，也不是玩家存档。

本项目全部使用 `res://` 路径引用。按用户要求删除 `.uid` 并忽略其重新生成的文件；不依赖 UID 加载脚本或场景。Godot 编辑器仍可能重新生成这些旁文件，删除后不影响当前工程的路径引用。以后改名或移动文件必须同步路径，并做引擎导入及启动检查。

## `.png.import` 与 `.godot/` 是什么

`items.png.import` 是图片旁边的导入配置与记录，描述 Godot 如何把原图转换为引擎使用的资源；压缩纹理等实际缓存通常在 `.godot/imported/`。音频和字体也会有类似导入记录。

本项目在 `.gitignore` 中忽略 `*.import` 与 `.godot/`，首次打开工程时由编辑器重新生成，因此图片旁出现 `.import` 是正常现象。文件被 Git 忽略，并不意味着编辑器不会在磁盘上创建它。

以后若需要持久保存特殊导入设置，应针对具体资源调整版本管理约定；不要把重要的定制设置只留在被忽略的文件里。

## 清理与提交

1. 在游戏目录运行 `git status --short`，分清已有改动与本次内容。该目录有独立仓库，不在父目录执行提交。
2. 临时文件移入独立的 `/tmp/paopaotang-*` 目录。保留原路径清单，方便恢复；不要连带移动原图、源码、存档或授权文件。
3. 新截图先放 `/tmp`，确定文档需要引用后，再选择少量成品放进 `docs/screenshots/`。项目根目录不放预览图。
4. 提交前查看暂存差异。新增必需资源、路径引用和文档一并核对；排除运行时、安装包、缓存及临时检查结果。

检查文件是否被忽略可用 `git check-ignore -v 文件路径`。harness 输出位置和隔离存档规则见 [harness 使用说明](harness.md)，素材更新流程见 [资源制作](资源制作.md)。

`/tmp` 可能被系统清理，只适合临时产物。需要长期保留的制作源文件和交付证据，应按用途放入资源目录或正式文档目录。
