# 玩法与数据约定

## 内容索引

地图和主题索引从零开始。当前地图 0～19 对应经典闯关，20～39 对应剧情二十节，40～43 为常夜洞窟；自由混战和组队对战可以选择全部地图。`new_round()` 的剧情选图使用 `20 + adventure_stage - 1`，图鉴任务预览读取 `Story.STAGES[].map`。增加或重排剧情地图时要同时处理这两处。

主题顺序为海港、森林、冰雪、沙漠、火山、工厂、糖果、星空、沼泽、遗迹、深海、空港、王城、洞窟。主题索引决定地表、箱体、装饰、背景、环境色与 BGM，不可只改一张背景。

道具目录共 29 项：索引 0 为空，1～18 为原有道具，19 为星币，20～25 为六种核心，26 为照明弹，27 为火把，28 为 PVE 专属高压核心。除空与地图专用星币外，共 26 种常规道具。`active` 占一个手持槽，`growth`、`mount` 与 `treasure` 拾取后直接生效。当前道具由 `hd_art.gd` 根据 `assets/art/atlas-regions.json` 裁切；旧 20×20 图集仍作为制作参考保留。

人物索引为 0～7，解锁阈值为 0、0、3、5、8、11、15、20；经典和剧情已通关节数取较大值。坐骑索引 0 表示无坐骑，1～3 为鸭、龟、兔。

## 实体状态

| 数据 | 关键字段 | 含义 |
| --- | --- | --- |
| `grid[y][x]` | 0 / 1 / 2 / 3 | 空地 / 墙 / 箱 / 坍塌 |
| 玩家 | `id`、`team`、`bot`、`character` | 席位、阵营、输入来源、造型 |
| 玩家移动 | `cell`、`visual`、`velocity`、`momentum`、`gait` | 连续位置、网格位置、移动反馈与动画 |
| 玩家状态 | `trap`、`grace`、`shield`、`mount_hp`、各效果计时 | 被困、保护、坐骑承伤及临时能力 |
| 泡泡 | `cell`、`owner`、`range`、`power`、`timer`、`element` | 占位、归属、射程、起爆强化等级、倒计时、属性 |
| 水柱 | `cell`、`time`、`owner`、可选 `element` | 格子上的短暂伤害，环境来源使用 owner=-1 |
| 箱体 | `cell`、`size`、`kind`、`hp`、`serial` | 锚点、占格、类型、耐久与单次命中去重 |
| 地形 | `terrain[cell].type` 与类型参数 | 传送、水流、开关、火把等附加机制 |
| 危险 | `hazards[].cells`、`wait`、`type` | 延迟生效的机关或怪物预警 |
| 掉落 | `drops[cell] = item_id` | 格子到道具的映射 |

普通移动以 `visual` 连续位置和小脚底碰撞体计算阻挡，再就近取整得到 `cell`。拾取、泡泡放置、机关和伤害使用网格位置；传送使用 `teleport()` 同时重置逻辑与视觉位置。新放置泡泡的离开许可由 `bubble_pass` 管理，不能让角色被自己的泡泡卡住。

## 关键机制

普通泡泡倒计时为 2.3 秒，低重力地图为 3.4 秒；泡泡强化每级缩短 0.1 秒，最多三级。爆炸前 0.7 秒显示范围预警。水柱撞墙或深渊停止，通常在箱体和泡泡处停止；穿透属性可越过每方向的第一只箱体，棱镜改变传播方向。相同路径还用于 Bot 的危险图与逃生判断。

护盾优先抵挡，其次由坐骑扣耐久，最后角色困泡八秒。队友碰到困泡角色可救援，敌人碰到则出局；同队水柱不伤队友，自己的普通水柱会伤自己。净化属性可以保护自己和队友。角色不等同于拥有 HP 的怪物。

普通箱、轮箱、加固箱与宝库耐久为 1、1、2、8。宝库覆盖 2×2，同一次爆炸或一组环境攻击按 `serial` 去重。奖励空间足够时可掉六件，周围受阻时会减少。爆炸先清旧掉落，避免刚生成的奖励被同次爆炸清除。

主动道具自动替换原手持道具，旧道具留在地上；`pickup_lock` 防止停在同格时反复互换。成长和坐骑不会占主动槽。检查拾取时要同时看位置插值、锁、磁铁远程拾取与已有手持物。

对战时间来自地图 `seconds`；剧情额外加 90 秒。归零后每五秒向内推进坍塌，原泡泡先爆炸，随后地块成为深渊，站在上面的角色出局。PVE 任务完成后仍需真人进入出口，不能仅凭任务计数直接结算。

## 剧情与 Bot

主任务包括收集后交付、接触营救、按序水柱点灯、护送并补给、守点、波次和 Boss。每节有两处支线，采用收集、停留或水柱激活。真人队伍每关按轻松、标准、挑战难度共享三次、两次、一次复苏，Bot 每关一次。队伍耗尽可复苏成员或倒计时进入最终限制后失败。

竞技 Bot 从 `danger_cells()` 计算危险，使用格子广度搜索逃生与寻路，再选择队友、敌人、诱饵和成长掉落。PVE 提供 `bot_target()` 与 `should_bomb()` 引导任务。新增机关必须让危险图获知攻击路径或预警时间，否则 Bot 可能无从避让。

## 存档兼容

新增统计要同时更新 `default_profile()`、读取默认值和显示内容。新增局外进度要定义旧存档缺字段时的行为；局内速度、容量、射程、属性计时默认不跨局保存。不要把 harness 的临时进度混入玩家存档。

当前文档描述实现约定，不保证所有边缘组合都已验收。行为修改后按 [开发与验收](开发与验收.md) 中对应条目检查。


地图使用 27×19 逻辑格，对战席位 2～8、真人 1～4，组队席位为 4、6、8。`SPAWNS` 包含八处位置，`round_spawns()` 按分组排列出生点；比分数组为八位。被困八秒，`try_move()` 触碰立即执行 `release_player()` 或 `kill_player()`。阵亡角色保留倒地贴图至下一局。天气由地图 `daynight`、`fog`、`night` 显式字段控制。


v4.7.5 的掉落权重、移速上限、坐骑耐久、属性阻挡、队伍缩放与地图对称规则见 [平衡调整](平衡调整-v4.7.5.md)。
